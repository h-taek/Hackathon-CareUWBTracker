# spike/ — 웹 GS 성능 스파이크 (F3 선행 게이트)

`plan/07`이 F3 착수 전 조건으로 건 게이트다: **"샘플 스플랫을 데모 머신 브라우저에서 렌더해
프레임레이트·로드시간을 실측한다. 부적합하면 별도 언리얼 창으로 폴백한다."**
그 숫자를 뽑는 일회성 페이지이며, **F3 본작업이 끝나면 이 폴더째 삭제한다**(대시보드는 이 페이지를
참조하지 않는다).

## 돌리는 법

1. 샘플 스플랫이 `../assets/splat/`에 있는지 확인(없으면 그쪽 README의 curl 명령으로 조달)
2. 서버 실행 후 <http://localhost:8080/spike/gs>
3. 씬을 고르고 `씬 로드` → 로드되면 `측정 시작`
4. 끝나면 `결과 복사`로 JSON을 뜬다

**데모에 실제로 쓸 맥에서 재야 의미가 있다.** 다른 기기의 숫자는 게이트 근거가 못 된다.

## 무엇을 어떻게 재나

두 구간을 이어서 잰다. 각 구간 앞 2초는 셰이더 컴파일·텍스처 업로드가 섞이므로 버린다.

| 구간 | 카메라 | 왜 |
|---|---|---|
| 궤도 | 씬 밖에서 한 바퀴 | 화면에 스플랫이 가장 많이 들어오는 부하 |
| 실내 | 씬 한가운데서 제자리 회전 | 스플랫이 겹쳐 그려지는 부하. **관제 화면이 이쪽에 가깝다** |

판정 기준은 평균이 아니라 **1% 저점**(가장 느린 1% 프레임의 평균 fps)이다. 데모 중 한 번
끊기면 평균이 좋아도 소용없기 때문이다.

- **45fps 이상** — 합격, 웹 GS로 진행
- **30~45fps** — 조건부. SH 0 · 1배 해상도로 낮춰 여유 확보
- **30fps 미만** — SH 0 · 1배 해상도로 재측정하고, 그래도 미달이면 언리얼 폴백 검토

## 조절 항목이 의미하는 것

- **구면조화(SH)** — 보는 각도에 따른 색 변화. 0이면 색이 고정되지만 메모리·연산이 가장 적다.
  실사 맵이 무거우면 여기부터 내린다.
- **정렬 워커** — 스플랫은 매 프레임 깊이순 정렬이 필요하다. 공유메모리(SharedArrayBuffer)를
  쓰면 워커에 데이터를 복사하지 않아 빠르다. 쓰려면 서버가 교차출처 격리 헤더(COOP/COEP)를
  보내야 하고, 이는 `server/static/handler.ts`에서 켜져 있다. 패널 제목 옆에 활성 여부가 뜬다.
- **렌더 해상도** — 레티나는 픽셀이 4배라 그만큼 무겁다. 1배로 낮추는 게 가장 확실한 여유다.
